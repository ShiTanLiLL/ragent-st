# Ragent 渐进式复现教学大纲

## 课程目标与进度说明

课程用 20 课重新发明一套可运行的 Java Agentic RAG 后端。每课都由上一阶段的真实不足推动，不按 Controller/Service/Repository 或设计模式名词切课。大纲只规划方向，不授权提前实现；开课时仍需根据当时代码和学生反馈生成/调整当前课教案。

- 当前进度：第 1～10 课已提交并推送；第 11 课正在让后台解析按 MIME 保留 Markdown 标题、段落和表格结构。
- 任务标记：`[ ]` 未完成，`[x]` 已由学生运行测试并完成课堂验收。
- 当前已有第 1～11 课教案；第 12～20 课不得提前生成教案。

## 第 1 课：先让程序答对一个问题

### 背景

项目尚不存在。客服希望程序能回答一条明确的退货政策，同时不知道时不能编造答案。

### 本课需求

输入包含“退货”的问题时返回固定政策；输入未知问题时返回明确的未找到提示。

### 任务

- [x] 把已知问题的输入和预期回答写成第一个失败测试。
- [x] 写一个直接、最小的 `KnowledgeAssistant` 实现并让测试通过。
- [x] 再用测试约束未知问题的诚实兜底。

### 主要技术点

JUnit 5、Arrange/Act/Assert、测试失败与通过、字符串输入输出；不引入 Spring、模型、数据库或接口。

### 预计影响

首次创建 `src/test/java` 和 `src/main/java` 下各一个类。

### 与上一课的关系

这是零起点，只建立最短业务闭环和 TDD 节奏。

### 完成标准

学生亲自运行两个测试并通过，能解释输入、输出和分支；代码中没有未来扩展层。

## 第 2 课：政策变多后，答案不能继续写死

### 背景

一个 `if` 能回答退货问题，但保修、物流、发票继续加入会让方法迅速堆满分支，也无法说明答案来自哪里。

### 本课需求

支持多条内存知识，用关键词找到最匹配的一条，并返回知识标题与正文。

### 任务

- [x] 用新增政策测试暴露硬编码分支的问题。
- [x] 从判断逻辑中分离出当前确实需要的知识数据。
- [x] 增加命中与未命中的排序/来源测试。

### 主要技术点

集合遍历、简单相关性计分、小型返回数据结构；在重复真实出现后进行第一次局部重构。

### 预计影响

修改助手类，按需求增加知识条目和值对象；不引入 Repository 或检索接口。

### 与上一课的关系

多知识需求让写死答案成为具体维护问题，数据与逻辑现在才有分离理由。

### 完成标准

多条政策能被正确选择，答案带来源，旧测试保持通过。

## 第 3 课：让长文档自动变成可查询的知识

### 背景

人工把每条政策写进 Java 集合既慢又容易漏，运营人员已有文本文件，程序需要自己读取和拆分。

### 本课需求

读取一个 UTF-8 文本/Markdown 文件，按段落切成可检索片段，并能回答片段中的问题。

### 任务

- [x] 用临时文件测试文档读取。
- [x] 实现最简单的空行分块。
- [x] 把片段送入已有匹配逻辑并验证完整链路。

### 主要技术点

文件字节/文本、编码、段落、Chunk 身份与顺序；首次形成“摄取 → 检索”的数据链。

### 预计影响

增加直接的文件读取与分块代码，知识数据由硬编码迁移到文件产生。

### 与上一课的关系

知识条目变多暴露录入成本，文档摄取由真实运营需求产生。

### 完成标准

测试文件无需改 Java 代码即可成为知识，空文件与正常文件的行为明确。

## 第 4 课：用户换一种说法也要找得到

### 背景

关键词只看字面。用户问“东西不想要了几天能退”，可能匹配不到写着“无理由退货期限”的片段。

### 本课需求

把问题和片段表示为向量，按余弦相似度返回最相关的片段。

### 任务

- [x] 用固定小向量写排序测试，先理解相似度而不连接外部服务。
- [x] 实现余弦相似度与 Top-K 排序。
- [x] 用一份可重复的向量夹具替换字面命中路径。

### 主要技术点

Embedding 的大白话解释、向量、余弦相似度、Top-K、浮点边界。

### 预计影响

Chunk 开始携带向量；检索代码从字符串匹配演化为向量排序。

### 与上一课的关系

真实问法与文档措辞不一致，迫使检索从字面走向语义。

### 完成标准

同义问法能在确定性测试中命中正确片段，学生能沿一个向量实例解释排序。

## 第 5 课：把语义检索接到真实模型

### 背景

手写向量只能验证算法，无法为任意新文档和问题生成语义表示。

### 本课需求

通过阿里云百炼的 OpenAI 兼容接口调用具体 Embedding 和通义千问聊天模型，根据检索证据组织自然语言回答。

### 任务

- [x] 用 HTTP 桩测试 Embedding 请求和响应解析。
- [x] 接通文档与问题的真实向量化。
- [x] 组装“问题 + 证据 + 回答约束”提示词并测试聊天请求。

### 主要技术点

HTTP/JSON、API Key、Prompt、检索与生成的边界、测试替身；仍只有一个供应商，不建 Provider 体系。

### 预计影响

增加一个具体模型客户端、配置读取和 RAG 回答流程。

### 与上一课的关系

向量排序已证明有效，现在才需要外部模型产生向量和最终回答。

### 完成标准

在桩测试中完成“问题 → 检索 → 有证据回答”，可选用真实 Key 做一次人工验收。

## 第 6 课：让浏览器和其他程序都能提问

### 背景

当前能力只能从测试或 Java 代码调用，真实用户需要稳定的网络入口和清晰错误响应。

### 本课需求

提供创建问答的 HTTP API，校验空问题，并返回统一但不过度抽象的 JSON。

### 任务

- [x] 写 API 层测试描述状态码和响应体。
- [x] 引入 Spring Boot Web 并暴露一个端点。
- [x] 增加参数校验和最小异常映射。

### 主要技术点

HTTP 请求/响应、Spring 容器、Controller、JSON、边界校验。

### 预计影响

项目变为可启动应用；首次出现 Web 层，但不机械拆成多 Maven 模块。

### 与上一课的关系

业务能力已可用，外部调用需求使 Web 框架有了现实位置。

### 完成标准

API 测试和应用启动测试通过，学生能用 curl 得到一个有证据回答。

## 第 7 课：答案很长时，先把已经生成的部分交给用户

### 背景

聊天模型可能几十秒后才返回完整答案，阻塞 HTTP 让用户误以为系统卡住，也无法停止无用生成。

### 本课需求

用 SSE 增量发送回答，分配单次 `taskId`，并支持取消仍在运行的任务。

### 任务

- [x] 定义最少的 meta/message/done 事件测试。
- [x] 将模型回调桥接为 SSE 增量。
- [x] 登记运行任务并实现一次取消路径与恰好一次收尾。

### 主要技术点

流式响应、回调、SSE、任务身份、取消、并发安全收尾。

### 预计影响

问答返回从完整字符串演化为流；出现仅为当前运行服务的任务登记。

### 与上一课的关系

HTTP 入口暴露出模型延迟，流式与取消由真实用户体验问题驱动。

### 完成标准

集成测试能观察有序事件，取消后不再发送正文且资源被释放。

## 第 8 课：让运营人员上传自己的知识

### 背景

服务器启动时读取固定文件不够，运营人员需要通过 API 添加知识，并知道文档目前是否可查询。

### 本课需求

创建知识库、上传纯文本文件、本地保存原文，同步完成分块和索引，并返回文档状态。

### 任务

- [x] 测试上传后产生文档与片段。
- [x] 保存本地文件并记录最小文档元数据。
- [x] 串起同步摄取，明确 `pending/running/success/failed`。

### 主要技术点

Multipart、文件所有权、文档/Chunk 数据、状态所有者、失败清理。

### 预计影响

增加知识库、文档和上传入口；数据暂存内存与本地目录。

### 与上一课的关系

用户问答入口已经可用，知识运营成为下一个真实角色和输入源。

### 完成标准

上传后能查询新内容，失败状态可观察，测试不依赖外部对象存储。

## 第 9 课：服务重启后，上传的知识不能消失

### 背景

内存中的知识库、文档、片段和向量随进程退出丢失，本地原文件仍在，却已经无法恢复归属和检索关系；向量规模也会继续增长。

### 本课需求

用 PostgreSQL 保存核心业务数据，并用 pgvector 保存/检索向量。

### 任务

- [x] 用容器化测试验证重启后的文档与片段恢复。
- [x] 设计当前确实需要的少量表和索引。
- [x] 将内存读写迁移到 JDBC，并验证向量相似度查询。

### 主要技术点

关系数据、主键和关联、事务、pgvector、迁移脚本；Repository 只在多处存取和替换需要出现后形成。

### 预计影响

数据从内存迁入 PostgreSQL；本地文件仍保存原文，避免同时引入对象存储。

### 与上一课的关系

上传产生了必须跨重启存在的状态，持久化现在才必要。

### 完成标准

数据库集成测试证明重启可恢复，文档元数据、Chunk 文本和向量归属一致。

## 第 10 课：上传不能一直占着请求线程

### 背景

大文档解析、Embedding 和索引耗时长；同步上传容易超时，用户也看不到处理进度和失败阶段。

### 本课需求

把摄取变成后台任务，保存任务/节点状态和错误，并允许查询进度与安全重试。

### 任务

- [x] 用可控执行器测试 `pending → running → success/failed`。
- [x] 上传只登记任务并快速返回。
- [x] 后台执行摄取，保存阶段耗时和错误。

### 主要技术点

异步任务、线程池、状态机视角、幂等重试、事务边界。

### 预计影响

增加摄取任务及查询端点；先用单进程执行器，不急着上消息队列。

### 与上一课的关系

持久化让任务状态有可靠落点，耗时问题才具备可观察和恢复条件。

### 完成标准

请求快速返回任务 ID，成功和失败路径均可查询，重复开始不会并行处理同一文档。

## 第 11 课：PDF、Markdown 和表格不能都按纯文本处理

### 背景

真实文档格式不同，固定空行分块会破坏标题层级、表格行和段落语义。

### 本课需求

按真实 MIME 选择解析方式，形成结构化 Block，再按预算产生稳定 Chunk。

### 任务

- [ ] 增加第二种格式夹具，让旧解析方案失败。
- [ ] 引入成熟解析库并实现 MIME 探测。
- [ ] 用标题、段落、表格 Block 调整分块，并保存展示文本与向量文本。

### 主要技术点

MIME 与扩展名区别、Parser 选择、结构化中间数据、Chunk 预算、第三方解析库边界。

### 预计影响

第二种解析实现使统一解析契约成为现实需要；摄取仍保持清晰固定顺序。

### 与上一课的关系

异步任务能承载更重解析，真实格式差异暴露单一实现局限。

### 完成标准

不同格式生成可预测片段，章节信息进入检索文本，错误格式在副作用前被拒绝。

## 第 12 课：不同知识源需要不同的加工步骤

### 背景

有的资料来自 URL，有的需要清洗或问题增强；把所有可选步骤塞进一个长方法会出现重复判断和难以定位的失败。

### 本课需求

允许为一次摄取配置一条线性的实际处理链，并记录每个节点结果；默认路径仍简单可用。

### 任务

- [ ] 用“远程获取 → 解析 → 分块 → 索引”需求暴露长方法分支。
- [ ] 在节点种类确实超过一种后抽取最小节点契约。
- [ ] 校验断链/成环并记录节点级日志。

### 主要技术点

上下文数据、链式执行、条件步骤、结构校验；此时再总结 Pipeline 思想。

### 预计影响

摄取从唯一固定路径演化出可配置路径，但不支持任意 DAG 或脚本插件。

### 与上一课的关系

格式和来源组合增加后，固定流程中的条件分支成为具体维护压力。

### 完成标准

默认上传与远程链均可运行，节点日志能指出失败位置，非法配置启动前失败。

## 第 13 课：用户追问“那怎么办”时，系统要知道“那”是什么

### 背景

每次请求彼此独立，代词和省略语无法理解；若把全部历史都发给模型，Token 成本会持续增长。

### 本课需求

保存会话与消息，加载最近若干轮帮助改写；历史过长时生成并持久化摘要。

### 任务

- [ ] 测试同一 `conversationId` 的消息顺序和用户隔离。
- [ ] 在问题改写前加载近期历史。
- [ ] 达到阈值后总结旧消息，并测试摘要水位。

### 主要技术点

会话与单次任务区别、消息角色、顺序、滑动窗口、摘要与 Token 预算。

### 预计影响

增加会话/消息/摘要数据和历史加载；流式完成或中断时保存不同消息状态。

### 与上一课的关系

知识问答链已稳定，真实连续使用暴露无记忆和无限历史两个相反问题。

### 完成标准

追问可正确消解，跨用户不可串话，摘要后上下文有界且关键事实保留。

## 第 14 课：知识库变多后，先弄清用户到底在问什么

### 背景

全库检索会混入无关部门资料；复杂问题可能包含多个子问题，直接拿整句检索会漏证据。

### 本课需求

改写并拆分问题，识别意图和知识库作用域；低置信度时回落全库，有歧义时先追问。

### 任务

- [ ] 用跨知识库同名概念测试证明全库检索的问题。
- [ ] 建立最小意图树和知识库绑定。
- [ ] 增加拆问、低置信回落和歧义引导测试。

### 主要技术点

查询改写、子问题、树形意图、置信度、检索作用域；区分“查哪里”和“怎么查”。

### 预计影响

检索请求携带作用域；Prompt 可按命中意图加入特定规则。

### 与上一课的关系

会话历史使改写有上下文，而多知识库规模使意图路由产生现实价值。

### 完成标准

明确问题走定向库，低置信问题不被错误拒绝，多子问题各自取得证据。

## 第 15 课：只靠一种检索，精确编号和自然语言难以兼得

### 背景

向量擅长语义却可能漏订单号等精确词；关键词擅长字面却不懂同义表达，单路排序也会把弱相关片段送给模型。

### 本课需求

并行执行向量与关键词召回，去重、RRF 融合、限制候选，再精排并加证据门槛。

### 任务

- [ ] 为两种通道各写优势场景与失败场景。
- [ ] 并行召回并让单通道失败可降级。
- [ ] 实现去重/RRF，接 Rerank，低相关整批拒绝。

### 主要技术点

并行 Future、超时、SearchChannel 抽象的产生、RRF、Rerank、召回/候选/上下文三段预算。

### 预计影响

单一检索实现重构为通道列表和后处理链；这是需求压力下形成的扩展点。

### 与上一课的关系

检索作用域已统一，多个通道可共享同一“查哪里”结论而只改变“怎么查”。

### 完成标准

语义和精确词场景都改善，超时通道不拖垮整次请求，送入模型的证据有上限和质量门槛。

## 第 16 课：一个模型服务不稳定时，问答不能整体失效

### 背景

外部模型会超时、空响应或限流；单一具体客户端已经成为可用性单点，不同任务对速度和能力要求也不同。

### 本课需求

配置两个候选模型，按 fast/standard/deep 档位选择；首包失败时切换，并用三态健康状态隔离故障节点。

### 任务

- [ ] 用故障客户端测试候选切换顺序。
- [ ] 从已有具体客户端抽出此时真正需要的共同协议。
- [ ] 实现首包探测、熔断 open/half-open/closed 与恢复测试。

### 主要技术点

Provider/Adapter 形成原因、模型能力档位、超时、流式首包、熔断和可恢复降级。

### 预计影响

模型调用从单实现演化为候选路由；配置在启动时校验。

### 与上一课的关系

主链已经依赖多种模型调用，外部不稳定现在成为最主要系统风险之一。

### 完成标准

首选故障能无重复正文地回退，健康节点恢复后可重新试探，错误配置启动失败。

## 第 17 课：并发上涨后，保护模型和后台任务

### 背景

多个用户同时提问或上传会耗尽模型额度和线程；单机内存队列在多实例下不公平且重启丢任务。

### 本课需求

为问答提供有界公平等待和租约，为摄取提供可靠消息投递，并阻止重复提交。

### 任务

- [ ] 先用压力测试重现无界并发问题。
- [ ] 引入 Redis 实现全局名额、排队、超时和唤醒。
- [ ] 在本地任务暴露丢失风险后引入消息队列与幂等消费。

### 主要技术点

信号量、租约、公平队列、Redis 原子操作、消息投递、幂等与事务消息边界。

### 预计影响

运行保护从单机结构升级为分布式协调；摄取执行从本地线程升级为可靠消费者。

### 与上一课的关系

模型已经具备节点级容错，现在要解决系统级容量与多实例一致性。

### 完成标准

并发不超过配置，排队可超时且名额必释放，重复消息不会重复替换索引。

## 第 18 课：答案不对时，要能回答“错在哪一步”

### 背景

用户只说“回答不准确”无法判断是改写、意图、召回、精排、Prompt 还是模型的问题，也需要查看原始来源。

### 本课需求

统一来源编号，保存用户反馈，并记录一次问答及关键节点的输入摘要、耗时、结果与错误。

### 任务

- [ ] 测试多个 Chunk 按文档去重成稳定来源。
- [ ] 保存点赞/点踩及原因。
- [ ] 增加 Run/Node Trace，并通过一个失败场景定位阶段。

### 主要技术点

证据与引用、反馈闭环、Trace Run/Node、横切关注点、内容脱敏和大小限制。

### 预计影响

问答结果带来源；管线节点产生可查询观测数据。只有重复追踪代码真实出现后才考虑注解/AOP。

### 与上一课的关系

多通道、模型路由和异步让失败位置增多，系统必须从“能跑”演化到“能解释”。

### 完成标准

用户能预览来源，反馈可关联消息，一次错误可从 Trace 定位到具体阶段。

## 第 19 课：开放任务不能再靠固定步骤写死

### 背景

固定 RAG 管线适合问答，但“先查政策，再查订单，符合条件就告诉我下一步”需要根据中间结果动态决定动作。

### 本课需求

引入一个基础 ReAct Agent，让模型在“知识检索”和一个本地只读业务工具之间迭代选择，并持久化会话状态。

### 任务

- [ ] 用脚本化模型事件测试 reasoning → tool → observation → answer。
- [ ] 把成熟 RAG 链封装成一个知识工具。
- [ ] 引入 AgentScope，限制最大迭代并保存/恢复状态。

### 主要技术点

ReAct、工具 Schema、动态工作流、Agent 状态、迭代上限；比较固定编排与自主决策的适用边界。

### 预计影响

新增 Agent 入口；原 RAG 不删除，而成为 Agent 可调用能力。

### 与上一课的关系

已有可观测、可靠的知识能力，才能安全地作为动态循环中的工具使用。

### 完成标准

Agent 能按中间结果选择是否继续调用工具，越界循环会收尾，下一轮能恢复会话。

## 第 20 课：把外部工具接进来，同时守住安全边界

### 背景

工具逐渐分布在不同服务，逐个手写适配成本高；某些工具会真实修改订单，模型不能绕过操作手册或用户确认。

### 本课需求

通过 MCP 发现和调用外部工具；只读工具直接执行，写工具等待确认；复杂操作先加载 Skill 手册。最后形成可配置、可部署的教学系统。

### 任务

- [ ] 连接一个 MCP Server，读取工具 Schema 并适配给 Agent。
- [ ] 根据只读声明与业务配置增加人工确认，参数只从服务端状态恢复。
- [ ] 为多步骤工具增加一份 Skill 手册与加载测试。
- [ ] 整理环境变量、数据库迁移、健康检查和容器启动说明，完成端到端验收。

### 主要技术点

MCP、Schema、Adapter、权限确认、渐进式 Skill、配置与部署；理解协议与业务安全各自负责什么。

### 预计影响

新增独立工具服务/客户端配置和确认入口；补齐部署资料，不复制原项目完整管理后台。

### 与上一课的关系

只有 Agent 已经拥有本地工具循环后，跨进程标准协议和安全控制才成为真实需求。

### 完成标准

端到端演示“提问 → 查知识 → 调 MCP → 用户确认 → 完成答复”，测试、配置、迁移和部署说明齐全，学生能解释整个数据流、状态流和每次抽象出现的原因。
